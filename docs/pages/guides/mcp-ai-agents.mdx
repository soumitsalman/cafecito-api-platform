# MCP Integration

Beans and Espresso use the same API-key authentication, but they answer different questions.

- Beans finds and verifies what publishers published.
- Espresso explains what happened and what it may mean.

## Authentication

  <a href="/settings/api-keys">Get API Key</a>
</Button>

Use the key as a Bearer token when connecting to https://api.cafecito.tech/beans/mcp or https://api.cafecito.tech/espresso/mcp.

## Beans tool selection

Start with the tool that matches the literal question.

| Tool | REST path | Answers |
| --- | --- | --- |
| searchArticles | GET /beans/articles/search | Which publisher Articles match this topic or filter? |
| getArticle | `GET /beans/articles/{id}` | What did this known Article say? |
| getLatestArticles | GET /beans/articles/latest | What was published most recently? |
| getTopHeadlines | GET /beans/articles/top-headlines | What is attracting attention in the fixed recent window? |
| getTrendingArticles | GET /beans/articles/trending | Which Articles are gaining attention? |
| getSimilarArticles | `GET /beans/articles/{id}/similar` | What related publisher reading exists? |
| getArticleMentions | `GET /beans/articles/{id}/mentions` | Where was this Article URL observed externally? |
| listSources / getSource | `GET /beans/sources` and `GET /beans/sources/{id}` | Which publisher metadata applies? |
| listCategories / listEntities / listRegions / listSentiments | GET /beans/categories, /entities, /regions, /sentiments | Which normalized filter values are accepted? |

Recommended Beans workflow:

1. Discover a filter value only when its spelling is unknown.
2. Search or select a feed based on the question.
3. Read the selected Article UUID from data[].id.
4. Retrieve detail only for selected Articles.
5. Follow similar or mentions only when the question needs them.
6. Send pagination.next_cursor unchanged as cursor.

content_type accepts every stored type listed in the Beans contract. Omit it to include all stored types; provider-only pr is not a Beans alias.

## Espresso tool selection

Use Espresso when the user asks what happened, what it means, impact, outlook, or supporting evidence.

| Tool | REST path | Answers |
| --- | --- | --- |
| searchEvents | GET /espresso/events | Which concrete developments match? |
| getEvent | `GET /espresso/events/{event_id}` | What is this selected Event? |
| getEventEvidence | `GET /espresso/events/{event_id}/evidence` | What supports this Event? |
| getEventSignals | `GET /espresso/events/{event_id}/signals` | Which Signals are related? |
| searchSignals | GET /espresso/signals | Which conclusions or outlooks match? |
| getSignal | `GET /espresso/signals/{signal_id}` | What is this Signal? |
| getSignalEvents | `GET /espresso/signals/{signal_id}/events` | Which Events support it? |

Do not use Beans to answer a structured Event or Signal question. Do not use Espresso when the user needs Article URLs, publisher text, or source coverage.
