# API conventions

## Authentication

All gateway REST and MCP requests use a Cafecito API key as a Bearer token:

~~~http
Authorization: Bearer YOUR-API-KEY
~~~

The gateway base URL is https://api.cafecito.tech.

## Product conventions

| Behavior | Beans | Espresso |
| --- | --- | --- |
| Collection pagination | limit plus opaque cursor | limit plus opaque cursor |
| Continue a collection | Send pagination.next_cursor unchanged as cursor | Send pagination.next_cursor unchanged as cursor |
| Empty collections | HTTP 200 with data: [] | HTTP 200 with data: [] |
| Canonical format | JSON | JSON |
| AI-agent formats | Use the REST/MCP JSON contract | YAML and TOON may be used where the Espresso contract supports them |

Beans V1 Article filters accept all stored content types listed in the Beans contract; omitting content_type includes all stored types. Espresso filters and resource meanings are separate. Use each product reference for route-specific limits, filters, schemas, and status codes: [Beans API](/api/beans) and [Espresso API](/api/espresso).

## Envelope rules

Collections return pagination and data, plus meta when the route exposes freshness metadata. Detail routes return data. Empty collections are successful HTTP 200 responses with data: [].

Follow the returned cursor exactly. Do not construct a cursor or substitute offset, page, pageSize, or size.

## Product choice

- Use Beans for publisher Articles, citations, full Article content when available, Source metadata, similar reading, and external Article mentions.
- Use Espresso for structured Events, Signals, impact, forecasts, and evidence relationships.

See [MCP and AI agents](/guides/mcp-ai-agents) for tool selection.
