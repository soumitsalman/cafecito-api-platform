# Beans News API & MCP

<Badge variant="default">v1</Badge><Badge className="badge-live">Live</Badge>

Beans finds and verifies what publishers published. It returns citable Articles, Source metadata, attention-ranked feeds, similar publisher reading, external Article mentions, and normalized filter discovery.

Use Espresso when the question is about structured Events, Signals, impact, forecasts, or evidence relationships.

## Choose a route by intent

| Need | Route | Returns | Provider parallel |
| --- | --- | --- | --- |
| Search the Article corpus | GET /beans/articles/search | Article collection | World News search-news, GNews search, NewsAPI.ai getArticles, NewsAPI.org everything |
| Retrieve one known Article | GET /beans/articles/{id} | Article detail | TheNewsAPI UUID lookup, World News retrieve-news |
| Monitor recent publication | GET /beans/articles/latest | Newest Articles | NewsData.io latest, Currents latest-news |
| Monitor fixed headlines | GET /beans/articles/top-headlines | Recent attention-ranked Articles | GNews and NewsAPI.org top-headlines |
| Monitor attention | GET /beans/articles/trending | Trend-ranked Articles with nullable metrics | World News top-news, TheNewsAPI top-news |
| Find related reading | GET /beans/articles/{id}/similar | Similar Articles, not guaranteed Story members | TheNewsAPI similar-by-UUID |
| Inspect external observations | GET /beans/articles/{id}/mentions | Social/forum mention observations | Beans extension |
| Resolve publisher metadata | GET /beans/sources or /beans/sources/{id} | Source records keyed by UUID | NewsAPI.org sources, provider source catalogs |
| Discover filter values | GET /beans/categories, /beans/entities, /beans/regions, /beans/sentiments | Normalized filter labels | Provider-specific catalogs |

Do not treat a Beans Article as an Espresso Event, a trend metric as an Espresso Signal, a similar Article as guaranteed Story membership, or a mention as another publisher Article.

## Public Article scope

The public V1 content_type values are all stored types from the proposal: blog, contract, earnings_report, enforcement_action, financial_report, lawsuit, news, official_statement, podcast, post, press_release, research_paper, site, technical_documentation, and whitepaper. Omit content_type to search all stored types. Do not treat provider pr labels as Beans aliases.

## Common request rules

| Rule | Contract |
| --- | --- |
| Authentication | Authorization: Bearer YOUR-API-KEY |
| Page size | limit is 1-100; default 20 |
| Continuation | Send pagination.next_cursor unchanged as cursor |
| Unsupported pagination | offset, page, pageSize, size, and other aliases |
| Empty collection | HTTP 200 with data: [] and next_cursor: null |
| Date inputs | from and to use inclusive UTC calendar dates in YYYY-MM-DD |
| Text query | q is route-specific natural-language search text |
| Semantic threshold | score_threshold is 0.0-1.0 and requires q |
| Content projection | full_content=true requests available Article content; it does not change matches |
| Filter logic | Different fields combine with AND; multiple include values within one field use OR; exclusion filters remove matches |
| Response format | JSON is canonical |

## Article filters

| Parameter | Meaning |
| --- | --- |
| q | Natural-language semantic Article search, maximum 512 characters |
| score_threshold | Minimum semantic similarity; only valid with q |
| ids | Exact Article UUIDs; search only |
| urls | Exact Article URLs; search only |
| content_type | Any stored type listed above; omitted means all stored types |
| sources / exclude_sources | Source UUID include/exclude filters |
| domains / exclude_domains | Exact Source domain include/exclude filters |
| authors | Case-insensitive exact byline values |
| categories / exclude_categories | Normalized category include/exclude filters |
| regions | Normalized extracted region labels |
| entities | Normalized extracted entity labels |
| sentiments | Categorical sentiment labels |
| tags | Fuzzy matching across normalized category, region, and entity labels |
| from / to | Inclusive publication bounds |
| full_content | Optional body projection |

Detail routes return { "data": { ... } }. Article content is omitted unless full_content=true; when requested but unavailable, content is null. Missing enrichment and Source display fields remain null or omitted according to the route schema. Trend metrics are nullable; Beans does not fabricate zero values.

Errors use HTTP status plus { "error": { "code": "...", "message": "..." } }. Successful responses do not repeat a status field.

## MCP workflow

Use these tools in this order when the question is about publisher material:

1. listCategories, listEntities, listRegions, listSentiments when a filter value is unknown.
2. searchArticles for broad or semantic retrieval.
3. getLatestArticles, getTopHeadlines, or getTrendingArticles for feed intent.
4. getArticle after selecting an Article UUID from data[].id.
5. getSimilarArticles for related publisher reading.
6. getArticleMentions for external observations.
7. listSources or getSource for publisher metadata.

The MCP server is https://api.cafecito.tech/beans/mcp. The same API key is used for REST and MCP. Pass cursor tokens unchanged.

## Planned, gated capabilities

Stories require persistent public Story UUIDs and persisted membership before publication. Count routes require bounded filters, approved query plans, and response tests. These capabilities remain in the design proposal and are intentionally absent from the live route list until their gates are met.
